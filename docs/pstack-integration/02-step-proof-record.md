# pstack integ step 2: add a pstack-neutral Proof record to the pre-submit gate

## Problem

The pre-submit gate checks `verification-before-completion`, the fresh-subagent OCR file pass, and waivers. It does not require the submitter to say what was actually proven, or on which surface. A user-visible change can ship on "unit tests passed" with no record that the real surface was never driven. Review has an **Evidence class**, but the author side has no matching record.

pstack's **principle-prove-it-works** and a project `verify-<app>` skill (generated by `create-verification-skill`) are the strongest producers of that proof, but nothing calls them.

## Proposal

1. In `references/pre-submit.md`, add a **Proof record** section. It is pstack-neutral and applies to `/git-issue-pr`, `/git-revise-pr`, `/git-revise-pr-force`, `/git-fix-conflict`, and scheduled lifecycle pushes. The record goes in the PR/MR description `## Verification` section, or the update comment when the description is not being edited:

   ```
   Proof: <command or skill run> -> <observed result>
   Evidence class: live job / real artifact bytes | executable unit tests | source-contract / regex tripwire | docs alignment
   Surface: <verify skill and feature driven> | none: <reason>
   Load-bearing fact: <fact> (level 1-5) | n/a
   pstack: present <version> [hooks run] | absent | off
   ```

   - Evidence class values match `references/review.md` word for word.
   - Inconclusive or wrong-surface is not a pass.
   - A user-visible change proven only by tests records `Surface: none: <reason>`.
   - Add "missing Proof record" to the gate's do-not-push conditions next to the missing waiver record.
2. In `references/pstack.md`, add hook rows:
   - **principle-prove-it-works** runs before the pre-submit gate on implement, revise, and conflict. It fills `Proof:` from a real run of the changed behavior.
   - When the repo has a `verify-<app>` skill and the diff touches a surface in its feature map, drive that feature and fill `Surface:`.
   - `create-verification-skill` does not run inside these modes unless the issue asks for it. Without a verify skill, the chat report recommends `/create-verification-skill` as separate work.
   - Fallback: `verification-before-completion` output fills `Proof:`, and the record says `pstack: absent`.
3. Add the umbrella's soft-pass rows that apply here to the pre-submit excuse table: "pstack is not installed, so proof is n/a", "Inconclusive on the real surface", and "I will create the verify skill in this PR".
4. `references/implement.md` step 15 and `references/revise.md` step 8: one clause each saying the description carries the Proof record.
5. `references/scheduled-automation.md`: scheduled pushes fill the Proof record with `pstack: off`.

## Acceptance criteria

- [ ] `references/pre-submit.md` defines the Proof record with the five fixed English labels, `Proof:`, `Evidence class:`, `Surface:`, `Load-bearing fact:`, and `pstack:`.
- [ ] Evidence class values in the Proof record are identical to the class names in `references/review.md`.
- [ ] Pre-submit gate step 7, or its equivalent, lists a missing Proof record as a do-not-push condition.
- [ ] The text states "Inconclusive or wrong-surface is not a pass" and requires `Surface: none: <reason>` for a user-visible change without a surface drive.
- [ ] `references/pstack.md` has hook rows for **principle-prove-it-works**, the `verify-<app>` skill, and `create-verification-skill`, each with trigger, evidence, and fallback.
- [ ] `references/implement.md`, `references/revise.md`, and `references/scheduled-automation.md` each point at the Proof record without copying it.
- [ ] `scripts/validate.py` asserts the five labels and the "Inconclusive or wrong-surface is not a pass" sentence in `references/pre-submit.md`, and asserts that `references/scheduled-automation.md` contains `pstack: off`.
- [ ] `SKILL.md` word count does not increase, and `python3 scripts/validate.py` passes.
- [ ] This PR's own description contains a filled Proof record.
